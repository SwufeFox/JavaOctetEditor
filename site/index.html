把保存这件事说清楚

先编辑，再应用，
最后明确导出。

每一步都有清楚的状态。编译失败保留原有内容，关闭或更换归档前，会检查你还没处理完的更改。

  1. 1

    编辑草稿

    标签页标记尚未应用的内容。后台刷新会保留你正在输入的新草稿。

  2. 2

    应用到内存

    源码编译成功后一起提交；应用后，原始归档仍保持不变。

  3. 3

    导出归档

    选择输出文件，确认替换已有内容。导出期间的新修改会继续保留。

Calculator.java修改示意
 public static int add(int a, int b) {−    return a - b;+    return a + b; }
应用后，依然由你决定何时导出。草稿状态与归档的导出状态分别显示。

修改已有类时，在当前 JDK 支持的范围内保留原目标版本；多版本归档中的版本化 class 作为资源保留。

Terminal
java -jar JavaOctetEditor.jar

请将 JavaOctetEditor.jar 替换为你下载的 JAR 文件名。使用完整 JDK 21 启动。

开始使用

一个 JAR，放进你的工具箱。

准备完整 JDK 21，获取构建产物，或从源码启动。

获取最新构建

在 GitHub Actions 中选择成功的构建，下载 Artifacts 中的归档，解压后运行其中的 JAR。

打开构建下载

下载构建产物需要登录 GitHub。JAR 包含应用依赖，运行仍需要 JDK 21。

从源码运行

在熟悉的环境里构建。

git clone https://github.com/SwufeFox/JavaOctetEditor.git
cd JavaOctetEditor
./gradlew run

Windows 使用 .\gradlew.bat run；运行 build 任务可生成包含依赖的 JAR。
